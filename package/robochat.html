robochat

Rhino plugin · v0.5.2 · updated 7/12/2026

Claude Code terminal docked in Rhino - the official CLI on your own subscription, no API keys. Built from: embedded Chromium (CefSharp) + xterm terminal UI; Python PTY sidecar; per-project workspaces with multi-chat registry and persistent memory; skill quick-invoke buttons and context-plugin presets; first-run setup wizard; clean uninstall command (RobochatUninstall). 0.5.2: changing the model on a brand-new chat now works right away. Before, if you opened a fresh chat and picked a different model before the chat had finished starting up, the change was silently dropped (you had to nudge the effort first, or flip to the terminal view and back, to make it take). Now the model change waits for the chat to be ready and then applies on its own. 0.5.1: Robohopper's skills now travel inside the Robohopper plugin itself, and Robochat keeps your working folder's copies in sync automatically - version-aware, and it never overwrites a skill you have edited (it flags it and offers an explicit Update instead). A Robohopper update is now announced the same way a Robochat update is - one small popup with a "don't show again" option - and only when Robohopper is actually installed, so it is never noise. If Robochat and Robohopper both have an update, the two notices never overlap: you see one at a time. 0.5.0: model and effort now change reliably from the menu. They used to relaunch the chat with a launch flag, which Claude Code ignores when it resumes a session, so the menu change silently did nothing (you set high, it drifted back). Now the menu sends the native in-session command, exactly what typing /model or /effort in the terminal does, and it sticks. The model label follows Claude's real current model instead of the one you requested, so it can no longer show a model you are not on. 0.4.25: the extra "auto" button introduced in 0.4.24 is removed - the permission row is back to the one gesture you know: click the name, the mode advances. Being in auto is now shown by the permission button itself lighting up (accent colour, white text) while the session really runs in auto - no separate switch, nothing that is sometimes not clickable. On models where Claude Code does not offer auto (currently Haiku: it answers "auto mode unavailable for this model" and falls back to asking), the row simply shows the real mode, with the reason in the tooltip. 0.4.24: the permission row now tells the truth about "auto" at a glance - the permission button lights up (accent colour, white text) while the session really runs in auto, and a small "auto" button appears next to it ONLY when pressing it does something: one click brings the same chat back into auto in a few seconds (conversation kept), whatever Claude Code does to the Shift+Tab cycle. On models where Claude Code does not offer auto at all (currently Haiku: it answers "auto mode unavailable for this model" and falls back to asking), Robochat now shows the real mode instead of a stale "auto", and the auto button stays out of the way until you switch back to a model that supports it. 0.4.23: model and effort switching is rebuilt to be deterministic - picking from the dropdown relaunches the same chat with your choice as a launch flag (a few seconds, conversation kept) instead of remote-driving Claude Code's terminal picker, which the latest Claude Code made unreliable by design; your model choice now sticks per chat. Claude's interactive questions (with option previews) render fully and are clickable again; chats with skill toggles no longer all share the same name; surface cards follow what is REALLY on screen, so they no longer vanish or appear late. Calibrated for Claude Code 2.1.207. 0.4.22: rolls back the 0.4.20 and 0.4.21 changes - they introduced instability on new chats in live use. This release is functionally identical to 0.4.19 (the reworked native permission control is kept). If you are on 0.4.20 or 0.4.21, please update. 0.4.19: the auto switch on the permission row is removed - every new chat already starts in auto, so the permission row is back to a single clean control: click the name to step the mode. 0.4.18: the auto switch on the permission row is now a labelled slide toggle (same style as the plugin switches, with a tooltip) - the bare dot introduced in 0.4.17 did not read as a control. 0.4.17: the permission control is native and reliable again on the latest Claude Code (2.1.206 removed "auto" from the Shift+Tab cycle and made it silent, which broke the old popup by design): clicking "permission" in the dropdown now steps the real mode one press at a time and the menu STAYS OPEN while you cycle; a new "auto" knob on the same row switches auto back on by seamlessly restarting the same chat (a few seconds, conversation kept). The mode label never lies anymore (it used to show "ask" while in auto), the switch is refused instead of losing text you typed but did not send, and the old permission popup is gone. 0.4.16: switching ON any plugin skill now switches the plugin itself ON automatically - the plugin's core context always travels with its members (before, a member armed while the plugin master was off was silently ignored at send, with no feedback). Works for every plugin, current and future. Also: the setup wizard's window dragging now binds late (groundwork for the upcoming Mac flavour); Windows behaviour unchanged. 0.4.15: every control click now lands - permission, effort, model, skill buttons and popup cards queue their action and run it the moment the terminal is ready (a click during startup used to die silently: buttons looked dead on a brand-new chat). A waiting click shows a visible "waiting for the terminal" state, double-clicks never fire twice, and switching chat clears stale actions. Claude Code's new MCP-consent startup dialog is now a proper clickable card (Confirm all / Reject all). The update popup title narrates the phase (Updating... then Updated, have fun!). 0.4.14: two toggle-reliability fixes - a default-on plugin toggle can no longer arm ITSELF mid-chat (a deficient state refresh silently re-armed it between two sends; toggles now only auto-arm at the start of a brand-new chat, and switching them off always sticks); and sending a message with armed toggles no longer shows a false "Message not sent - text restored" banner 10 seconds later (the delivery receipt now tracks the message itself, so the "skills loaded" confirmation works again and the banner only appears when a message is REALLY lost). 0.4.13: reliability pass - your plugin toggles no longer reset by themselves while Grasshopper is running (a background refresh was silently reverting them); an uninstalled plugin no longer shows up (or self-arms) in the toggle bar; the effort level you pick now STICKS across chat switches and restarts (it silently fell back to medium); the permission popup follows the new Claude Code mode cycle (auto / ask / accept edits / plan), its buttons respond reliably, and if a mode can't be reached it shows where you really are instead of dying silently. 0.4.12: the "plugin" list now shows from the start (even before a catalog is built) and fills in LIVE as a plugin vendor prints its catalog - no Rhino restart needed to see new plugins; and the plugin toggles in the grid panel are now reliably clickable. 0.4.11: if Claude Code isn't installed, Robochat no longer fails silently - a clear blocking window asks you to install it (one button runs the official installer) and clears itself the moment Claude is ready. 0.4.10: sign-in is now reliable end to end - when Claude reports "signed in, press Enter", Robochat finishes it for you and shows a clear "Signed in" card instead of a false "closed" message. A new chat inherits the last-viewed chat's setup instantly (before you type): promoted skills and packages, their order, and armed toggles. 0.4.9: the taskbar keeps items in the order you added them (oldest left), so you can organise the space; a brand-new chat inherits the previous chat's whole setup - promoted skills and packages, their order, and armed toggles (a frozen skill comes back armed). 0.4.8: the plugin list is now a grid panel that opens over the chat (no more clipping), scrolls with the app's own thin scrollbar, and keeps its place while you flip toggles; an armed plugin lights the accent colour. A brand-new chat inherits the previous chat's manager setup (same toggles, same taskbar) instead of starting blank. 0.4.7: a "plugin" list next to the skill toggles - every Grasshopper plugin on your machine becomes a per-plugin skill you can switch on (all off by default); suite plugins show as plain toggles, no nested menu; sign-in is even more robust (the code is ferried straight to the sign-in prompt, never the chat); Claude Code auto-install is hardened (no hang, no orphan, longer timeout for slow links). 0.4.6: sign-in made solid (the pasted code now reaches the sign-in prompt from the card AND the message box; the browser comes to the front; a clear Retry card when the sign-in window closes; a subtle loading dot while sign-in prepares); window Floating/Tab setting no longer shows a stale choice; setup polish (Finish hides while installing). 0.4.5: guided sign-in card (one click opens the browser, one box pastes the code - both Claude account and Console paths); wizard-return fix after updating from older versions. 0.4.4: setup wizard returns after an uninstall (onboarding tied to the installation); "Update catalog" manager button (regenerates a vendor's component catalog only when it lags the live Grasshopper census); Claude-version notice fully silent. 0.4.3: new icon everywhere; one-shot suite markers (fixes cross-app wizard inhibition) + live cwd channel + dock choice via marker; Robino capability; skill-preset popup with instant pill feedback and auto-promotion of newly deposited suite plugins; 3-tier skill manager colors; clean single bubble for sends with armed skills. 0.4.2: suite skill-plugins visible from chat start with once-per-chat send memory (re-arms after compaction), live workspace marker for suite members.

How to install robochat

  1. Click Install in Rhino to open Rhino's Package Manager with robochat selected, or run _PackageManager inside Rhino and search for robochat.On the computer running Rhino, run _PackageManager and search for robochat.
  2. Or install it from a terminal (assumes a default Rhino 8 installation):
    Windows (PowerShell)
    & "C:\Program Files\Rhino 8\System\Yak.exe" install robochat
  3. Or download a .yak file and drag it onto an open Rhino window.
    • robochat-0.5.2-rh8_0-win.yakWindows · Rhino 8.0

Restart Rhino once the install finishes.
